## 함께 제공되는 주문 처리 애플리케이션

이 폴더에는 "파이썬으로 구현하는 클린 아키텍처" 11장에서 설명하는 주문 처리 시스템의 개념 증명 구현이 포함되어 있다. 아키텍처 위반이 있는 레거시 애플리케이션에서 클린 아키텍처 원칙을 따르는 깔끔하고 잘 구조화된 시스템으로의 변환 과정을 보여준다.

## 개요

주문 처리 시스템은 사용자가 다음을 수행할 수 있는 간단한 Flask 애플리케이션이다:

1. 사용 가능한 제품 조회
2. 여러 항목이 포함된 주문 생성
3. 결제 처리 (시뮬레이션)

이 애플리케이션은 11장에서 설명하는 피처 플래그 변환 패턴을 보여준다:

- **단일 라우트 구현**: `/orders` 엔드포인트가 피처 플래그를 사용하여 레거시 구현과 클린 구현 중 선택
- **레거시 구현**: 11장에서 논의한 아키텍처 문제를 보여주며, 얽힌 의존성, 혼합된 비즈니스 로직, 라우트 핸들러에서의 직접 데이터베이스 접근 포함
- **클린 아키텍처 구현**: 적절한 관심사 분리, 도메인 주도 설계, 깔끔한 아키텍처 경계를 갖춘 리팩토링된 애플리케이션을 보여줌

### 인터페이스 이해

홈 페이지에는 두 가지 옵션이 표시된다:
- **레거시 구현**: 이 버튼을 클릭하면 피처 플래그 설정과 관계없이 레거시 구현을 명시적으로 사용한다
- **클린 아키텍처 구현**: 이 버튼을 클릭하면 클린 아키텍처 구현을 명시적으로 사용한다


## 애플리케이션 실행

[시작하기](../README.md#2-getting-started) 섹션의 지침에 따라 환경을 설정했는지 확인한다.

### 피처 플래그 제어

애플리케이션은 `USE_CLEAN_ARCHITECTURE` 환경 변수를 사용하여 어떤 구현이 요청을 처리할지 제어한다. 이는 11장에서 설명하는 변환 패턴으로, 단일 라우트가 구현 간에 선택하는 방식을 보여준다.

### 애플리케이션 시작

```bash
cd EcomApp

# 레거시 구현
USE_CLEAN_ARCHITECTURE=false python main.py

# 클린 아키텍처 구현
USE_CLEAN_ARCHITECTURE=true python main.py

# Windows에서
set USE_CLEAN_ARCHITECTURE=true && python main.py
```
